# Install with: pip install -r requirements-reference-lock.txt
#
# IMPORTANT: pinning these versions is necessary but not sufficient for
# bit-identical results. We verified directly (same seed, same code,
# torch 2.11.0 vs 2.14.0, same arm64 Mac) that RiskBudgetLSTM's seeded
# weight init AND its full forward pass are bit-identical across those
# two torch versions on the same machine -- so the torch-version
# difference between Nilay's Mac (2.14.0) and AnnaLisa's Colab (2.11.0)
# is NOT, by itself, what produced the frozen-LSTM validation Sharpe gap
# (0.411/0.489 archived vs 0.380/0.418 Colab). The remaining, uncontrolled
# difference is CPU architecture: Nilay's Mac is arm64 (Apple Silicon),
# Colab's CPU runtime is x86_64 -- different vectorized instruction sets
# and BLAS backends change floating-point summation order inside matrix
# multiplications, which is exactly the kind of difference PyTorch's own
# docs warn can change results "between... different platforms" even
# with everything else held fixed. This also reaches the cvxpylayers
# convex solve inside training (its KKT linear algebra depends on
# numpy/scipy), not just torch's own ops. Running on matching x86_64
# hardware (i.e. actually executing the canonical run on Colab, not a
# same-version install on a different CPU architecture) is what this
# pin is for.
#
# Source: Slack thread, 2026-10-03/04 (AnnaLisa Aaron's environment
# report + Nilay's Mac-side torch 2.11.0-vs-2.14.0 isolation test).
